SimpliLoad Azure Deployment Guide

Overview

SimpliLoad is a lightweight, Docker-based utility that enables IBM Cognos Analytics users to run reports through the REST API using a clean, modern interface. This guide explains how to deploy SimpliLoad using the Azure Marketplace offering, including VM provisioning, configuration, access, and connectivity to Cognos Analytics.

Prerequisites

IBM Cognos Analytics

SimpliLoad requires IBM Cognos Analytics 12.1.3 or later. Earlier versions are not supported because required REST API endpoints are unavailable.

Azure Requirements

  • An active Azure subscription.
  • Permission to create virtual machines, networking resources, and public IP addresses.

User Requirements

  • Cognos REST API URL.
  • Cognos API key.
  • Ability to configure firewall rules if Cognos is hosted on-premise or behind a VPN.

Deployment Steps in Azure Portal

1. Start the Deployment

Open the Azure Marketplace listing for SimpliLoad, select your desired plan (Trial, Single, or Unlimited), and click Create to launch the Azure deployment wizard.

2. Basics

Configure the foundational Azure resource settings for your virtual machine:

  • Subscription: Select the active Azure subscription where billing and resource ownership will be managed.
  • Resource Group: Choose an existing resource group or create a new dedicated one (e.g., rg-simpliload-prod) to keep all deployment assets grouped logically.
  • Region: Select the Azure region closest to your users or your hosted IBM Cognos Analytics environment to minimize network latency. Note: Depending on your subscription context or pre-selected scope, this prompt may be pre-populated or omitted automatically by the portal.
  • Virtual Machine Name: Enter a unique identifier for the virtual machine resource (defaults to simpliloadvm).
  • Admin Username: Enter the administrative username for logging into the virtual machine (avoid generic names like root or admin).
  • Admin SSH Public Key: Paste your SSH RSA public key string (starting with ssh-rsa) for secure Linux authentication. If you need to generate a new key pair, open PowerShell and run: ssh-keygen -t rsa -b 4096 -f "$env:USERPROFILE\.ssh\id_rsa" (the public key will be saved to $env:USERPROFILE\.ssh\id_rsa.pub).
  • Application Name: Specify a name associate the managed application (ie. simpliload-app).
  • Managed Application Resource Group: Specify or accept the managed resource group name where Azure will automatically provision and isolate the underlying solution resources and stock networking components.

VM Size

Select the hardware tier appropriate for your workload capacity:

  • Trial Plan: Restricted to Standard_D2s_v4 (2 vCPUs, 8 GiB RAM).
  • Single and Unlimited Plans: Flexible scaling options including Standard_D2s_v4, Standard_D4s_v4, or Standard_D8s_v4 based on concurrent report volume.

3. SimpliLoad Configuration

Configure initial application credentials and network access parameters:

  • SimpliLoad Admin Username: Set the primary administrator username for logging into the SimpliLoad web application.
  • SimpliLoad Admin Email: Specify the contact email address for the SimpliLoad administrator.
  • SimpliLoad Admin Password: Set a secure password for the primary administrator account (minimum 12 characters).
  • Additional Allowed Hostnames / Load Balancer FQDN: Optional. Enter comma-separated external hostnames or domain names permitted to access the application. The VM name is included automatically.
  • Cognos Allowed Hosts: Enter the hostnames or IP addresses of your IBM Cognos servers (comma-separated).

4. TLS Certificates

SimpliLoad secures all web traffic using HTTPS. You must choose how application and CA certificates are provisioned during deployment:

Organization-Provided Certificates (Recommended for Production)

If your enterprise uses internally signed or enterprise CA certificates, upload the corresponding PEM-encoded files:

  • TLS Certificate (server.crt): Upload your PEM/CRT public certificate or certificate chain file.
  • TLS Private Key (server.key): Upload your PEM private key file.
  • Cognos CA Certificate (cognos.pem): Optional. Upload the PEM CA certificate required to verify connections to your Cognos server over SSL/TLS.

SimpliLoad automatically mounts these credentials into /opt/simpliload/deploy/certs/ for the NGINX reverse proxy container to ensure secure, trusted connections.

Automatically Generated Self-Signed Certificate (Default)

If you leave the certificate upload fields blank, SimpliLoad automatically generates a secure self-signed certificate upon first boot. While fully encrypted, your browser will display an initial security warning until you trust the certificate locally or replace it later. If a public IP address is configured, it is automatically injected as a Subject Alternative Name (SAN).

5. Networking & Public IP

Configure networking settings for your deployment:

  • Managed Network: SimpliLoad automatically deploys using a stock network configuration within the managed resource group, streamlining setup without requiring custom virtual network or subnet provisioning.
  • Public IP Address: Select New to create a dynamic or static public IP, or select None to keep the virtual machine entirely private within your network.
  • DNS Name Label Prefix: If you choose to enable a public IP address, enter a unique prefix to establish an Azure-managed fully qualified domain name (FQDN), such as <prefix>.<region>.cloudapp.azure.com.

6. Review + Create

Azure runs a final automated validation check against your parameter inputs. Once validation passes, click Create to provision the infrastructure and trigger the automated installation script.

Post-Deployment Steps

Accessing SimpliLoad

SimpliLoad enforces an allowed-hosts list for security. During deployment, the VM's hostname and any provisioned public IP address are automatically added to ALLOWED_HOSTS.

Public Access

If deployed with a public IP, you can access SimpliLoad using your configured DNS label or public FQDN, for example:

[https://simpliload-prod.eastus.cloudapp.azure.com/](https://simpliload-prod.eastus.cloudapp.azure.com/)

Private / VNet-Peered Deployments

If you opted out of a public IP to keep SimpliLoad isolated within your network:

  • VNet Peering: Connect your internal corporate or application Virtual Network to simpliload-vnet to route traffic securely over Azure’s private backbone.
  • Private DNS: Create an entry in your Azure Private DNS Zone or corporate DNS server pointing an internal hostname directly to the VM's private IP address.
  • Certificates: Ensure your TLS certificate covers your internal domain name or private IP to prevent browser security warnings.

Logging Into the VM (Optional)

SSH access is available via RSA key authentication. If you generated your key using the default path ($env:USERPROFILE\.ssh\id_rsa), standard SSH clients will automatically use that key: 

ssh <admin-user>@<hostname-or-private-ip>
Security Note: Port 22 is not open by default. If you require administrative SSH access, you must configure an inbound network security group rule or access the VM through a private bastion or VPN connection.

Docker containers are located under:

/opt/simpliload/

Connecting to Cognos

All Cognos configuration is performed inside the SimpliLoad UI.

On the Settings page, enter:

  • Cognos REST API URL
  • API Key

Click Test to verify connectivity.

Updating SimpliLoad

To update SimpliLoad:

docker compose pull
docker compose up -d

Troubleshooting

This section provides practical guidance for diagnosing and resolving common issues encountered during deployment or operation in Azure. Each item includes likely causes, recommended fixes, and steps for reviewing logs inside the SimpliLoad VM.

Invalid Certificate Errors

Common Causes:

  • The Cognos CA certificate is missing or not in PEM format.
  • The Cognos CA certificate path in .env is incorrect.
  • Hostname verification is enabled but the Cognos certificate CN/SAN does not match.
  • The VM’s HTTPS certificate (self-signed or organization-issued) is unreadable by the container.

Fixes:

  • Verify the Cognos CA certificate exists on the VM and is valid PEM.
  • Confirm the corresponding path in .env points to the correct file.
  • Ensure the Cognos server certificate’s CN or SAN matches the hostname used in the SimpliLoad Settings page.
  • Check file permissions for the installed certificate and key inside the VM.

Connection Failures to Cognos

Common Causes:

  • Cognos is not reachable from the Azure VM.
  • Firewall rules or network ACLs block outbound traffic.
  • Incorrect Cognos hostname or port in the Settings page.
  • COGNOS_ALLOW_HTTP=false in .env while Cognos is only serving HTTP.

Fixes:

  • From the VM, test reachability using curl -v https://your-cognos-host or curl -v http://your-cognos-host.
  • Verify that outbound traffic from the VM to Cognos is allowed by your network team.
  • Update the Cognos REST API URL in the Settings page to match the actual hostname and port.
  • If Cognos is only available over HTTP and your organization accepts that risk, set COGNOS_ALLOW_HTTP=true in .env and restart the stack.

Authentication Issues

Common Causes:

  • The Cognos API key was copied incorrectly (extra spaces, hidden characters).
  • The API key has expired.
  • The API key has been locked in Cognos.
  • The API key was deleted or regenerated but not updated in SimpliLoad.
  • The Cognos user associated with the API key lacks permission to access the selected reports.
  • The Cognos user account is disabled or suspended.

Fixes:

  • Open Cognos Analytics → Manage → Accounts → (User) → API Keys and verify the key is active, not expired, not locked, and not deleted.
  • Re-copy the API key carefully and paste it into the SimpliLoad Settings page.
  • If the key is locked or expired, generate a new API key.
  • Ensure the Cognos user has access to the folders and reports SimpliLoad will execute.
  • If the user account is disabled, re-enable it or create a new API key.
Important: If an API key is locked, expired, or deleted in Cognos Analytics, it cannot be recovered. A new key must be generated and updated in the SimpliLoad Settings page.

Slow or Stalled Report Execution

Common Causes:

  • Insufficient ASGI worker threads for concurrent workloads.
  • Long-running Cognos reports exceeding the timeout limit.
  • High CPU usage on Cognos or the SimpliLoad VM.
  • Network latency between Azure and Cognos.

Fixes:

  • Edit .env on the VM and increase ASGI_THREADS, then run docker compose up -d to apply changes.
  • Raise SIMPLILOAD_RUN_TIMEOUT_SECONDS in .env for complex reports and restart the stack.
  • Review Cognos server performance and dispatcher load, and consider resizing the SimpliLoad VM if CPU saturation is observed.
  • Ensure the VM is deployed in a region or network topology that minimizes latency to Cognos.

Container Startup Errors

Common Causes:

  • Uploaded certificates are invalid or not in a supported format.
  • PostgreSQL container failed to initialize due to invalid credentials or disk issues.
  • Volume permissions preventing PostgreSQL from writing data.

Fixes:

  • Verify that uploaded certificates are valid PEM files and were accepted during deployment.
  • Ensure database credentials in .env have not been modified after deployment.
  • Check filesystem permissions and confirm the VM's OS disk is healthy and writable.

Important File Locations

The SimpliLoad VM stores all configuration files, certificates, and Docker resources under a single directory. These files are useful when troubleshooting, enabling DEBUG logging, or verifying certificate installation.

  • Application Directory:
    /opt/simpliload/
    Contains the Docker Compose stack, environment file, certificates, and support scripts.
  • Environment File:
    /opt/simpliload/.env
    Stores all runtime configuration values, including Cognos settings, ASGI thread counts, timeout values, and logging level.
  • Certificates:
    /opt/simpliload/deploy/certs/
    Contains the HTTPS certificate and key used by NGINX, as well as any Cognos CA certificate uploaded during deployment.
  • Docker Compose File:
    /opt/simpliload/docker-compose.yml
    Defines the SimpliLoad services (web, nginx, db) and their configuration.
  • Log Files (via Docker): 
    docker compose logs -f simpliload-web-1
docker compose logs -f simpliload-nginx-1
docker compose logs -f simpliload-db-1
    Logs are streamed from containers rather than stored as files.

These locations are consistent across all Azure plans and do not change when resizing the VM or updating SimpliLoad.

Recommended Diagnostic Workflow:

  1. Start with docker compose logs -f simpliload-web-1 to identify application-level errors.
  2. Check docker compose logs -f simpliload-nginx-1 for certificate or routing issues.
  3. Review docker compose logs -f simpliload-db-1 for database initialization or storage issues.
  4. Temporarily set LOG_LEVEL=DEBUG in .env for deeper insight into Cognos REST interactions, then run docker compose up -d to apply changes.
Note: Always return LOG_LEVEL to INFO after troubleshooting to avoid excessive log output.
